# 一键部署软路由（Ubuntu 通用版）方案 v1

目标：把现在散在 软路由主机 家目录的那套东西，做成**能发给同学、在他自己的 Ubuntu 上一键变软路由**的安装包，同时能被 Windows 端的「网络面板」遥控部署。

---

## 0. 现状与差距

已有（已验证可用）：16 个脚本 + ua3f + bitsrun，全部绑定在 某一台 Ubuntu 小主机、`eno1` + `wlp2s0` 这两个网卡名、srun 这一种认证。

做通用版要补的差距：

| 差距 | 说明 |
|---|---|
| 网卡名写死 | 别人可能是 `enp3s0` / `eth0` / `wlan0`，必须探测 |
| 认证写死 srun | 同学可能是普通宽带 DHCP、PPPoE，或别的校园网客户端 |
| 拓扑写死 | 不是每人都有"有线 WAN + 无线 AP"两块网卡 |
| 无安装程序 | 现在是 scp 散装文件，没有安装/升级/卸载 |
| 无服务化 | 现在靠桌面脚本 + 手动启停；同学机器重启就没了 |
| 无自检 | 出问题只能问我 |
| 伪装项无开关 | TTL/IPID/mDNS 这套只对校园网 Portal 有用，普通宽带反而多余 |

## 1. 支持的拓扑（必须先定，脚本按拓扑生成配置）

| 代号 | 拓扑 | 硬件要求 | 典型场景 |
|---|---|---|---|
| **A** | 有线 WAN → 无线 AP 当 LAN | 1 有线 + 1 支持 AP 的无线 | 你现在这台（也是同学笔记本最常见的情况）|
| **B** | 有线 WAN → 有线 LAN | 2 块有线网卡 | 台式机/软路由盒子，最理想 |
| **C** | 无线 WAN（连手机热点/宿舍 WiFi）→ 有线 LAN | 1 有线 + 1 无线（无线作客户端）| 笔记本，用别人 WiFi 中转 |
| **D** | 单网口单无线（无线 WAN + 无线 AP）| 1 无线 | 少见且不稳，**不推荐**，只检测不安装 |

安装向导第一步就是选拓扑，选完自动探测候选网卡并让用户确认。

---

## 2. 认证方式（插件化，可跳过）

| 方式 | 说明 | 是否需要额外二进制 |
|---|---|---|
| `none` | 插上就有网（大多数宿舍/家用宽带） | 否 |
| `pppoe` | 宽带拨号 | 否（nmcli 内置） |
| `srun` | 深澜 Portal（你学校用这个）| bitsrun |
| `manual` | 装完自己点门户登录，脚本只保证 NAT 通 | 否 |

**关键决定：bitsrun / ua3f 不打包进安装包**，安装时按需从 GitHub Release 下载；下载失败则跳过该功能并在报告里标明。理由：
1. 许可证合规——ua3f 是 GPL 系，直接分发二进制要附带源码与声明（**待核实具体条款**）
2. 包体积从 25MB 降到 <1MB，微信/QQ 发得出去
3. 版本能跟上游

## 3. 安装包结构

```
GrayRouter-Deploy-1.0/
├── install.sh              主安装（图形向导 zenity；无桌面自动降级为终端问答）
├── uninstall.sh            卸载 + 回滚
├── doctor.sh               环境体检，只读，输出可复制的报告
├── routerctl               命令行：setup / start / stop / status / logs / selftest / report
├── lib/
│   ├── common.sh           日志、时间戳备份、journal（记录做过的动作，供回滚）
│   ├── detect.sh           网卡枚举、AP 能力检测（iw list）、端口占用检测
│   ├── topology.sh         拓扑选择与校验
│   └── auth.sh             认证方式：none / pppoe / srun
├── templates/
│   ├── ap.nmconnection.tpl     无线 AP（WPA2，channel 自动避让）
│   ├── nat.nft.tpl             NAT + FORWARD
│   ├── ttl.nft.tpl             TTL 统一（可选）
│   ├── ua3f.service.tpl        systemd 单元
│   ├── ua3f.config.yaml.tpl    TPROXY + ipid（可选）
│   └── grayrouter.service.tpl  开机自动起 AP + NAT
├── bin/                    16 个已验证脚本（全部参数化，从 /etc/grayrouter/config.env 读）
├── assets/                 .desktop 图标、拓扑示意图
├── docs/
│   ├── 说明.txt             中文三步上手
│   ├── TROUBLESHOOTING.md   常见故障（没网 / AP 起不来 / 能连不能上 / IP 冲突）
│   └── 报告怎么发回来.txt
├── VERSION
└── checksums.sha256
```

安装后系统侧落点（干净、可卸载）：

```
/etc/grayrouter/config.env          参数（chmod 600，含密码）
/opt/grayrouter/                    bin/ lib/ templates/
/var/lib/grayrouter/                备份、日志、journal
/etc/systemd/system/grayrouter-*.service
/usr/local/bin/routerctl
~/.local/share/applications/*.desktop   桌面图标
```

## 4. 安装流程（install.sh 的 9 步）

1. **预检**：Ubuntu/Debian？内核版本？root？`nmcli`/`nft`/`iw` 是否存在？缺失则提示 `apt install` 命令并可自动装
2. **体检**（doctor）：列出所有网卡、驱动、是否支持 AP 模式、是否已装 clash/v2ray 占 7890 等端口、`ip_forward` 现状
3. **选拓扑**（A/B/C）→ 确认 WAN 网卡 / LAN 网卡
4. **填参数**：SSID、密码（≥8 位，强制）、LAN 网段（默认 `192.168.50.1/24`，**自动检测冲突**，冲突就换 `.60.1`）
5. **选认证**：none / pppoe / srun（srun 要账号密码，存 600 权限文件）
6. **选加固项**（默认关，仅当选了 srun 时提示开启）：TTL 统一、IPID 改写、mDNS 只走 LAN、DHCP 主机名伪装
7. **安装**：备份 → 写配置 → 装 service → 装 routerctl → 建桌面图标
8. **自检**：起 AP → 起 NAT → 从 WAN 侧验证出网 → 跑一遍 `router-status`，输出**一段可复制的报告**
9. **失败即回滚**：按 journal 逆序撤销，恢复 `autoconnect`，删临时文件，打印失败原因 + 报告

幂等：重复运行会检测到已安装，给三个选项——**修复 / 重装 / 升级**。

## 5. Windows 端配合（NetPanel 新增「部署」栏目）

```
① 目标：手填 IP + 用户名，或点「扫描本网段」自动找（含常见的 .50.1 / .137.x 热点网段）
② 点「一键部署」：
   打包 tar.gz（本地）→ scp 到 /tmp → ssh -t 执行 install.sh
   sudo 提示透传到内嵌终端，密码用户自己敲（不经过程序/AI）
③ 实时进度：上传 / 体检 / 装服务 / 自检，逐行滚动显示远端输出
④ 完成后：拉取体检报告显示；把这个 SSH 目标写进 settings.json；
   状态页下次刷新直接读到「模式 2·软路由」
⑤ 另外三个按钮：修复 / 升级 / 卸载（同一通道）
```

没有 Windows 端的同学：把 zip 解压，双击 `install.sh`（或 `bash install.sh`）即可，效果一样。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 同学无线网卡不支持 AP 模式 | 体检阶段就检测 `iw list` 的 AP 支持；不支持 → 明确告知并改用拓扑 B/C，不硬装 |
| Ubuntu 版本差异（22.04/24.04/26.04，netplan 与 NM 并存） | 能力检测优先用 nmcli；netplan 只用于恢复现场 |
| 装完把同学原来的网络搞坏 | 全程不改 WAN 网卡既有配置，只**新建**一个 AP profile + 规则；卸载逆序恢复；所有被改文件先 `.bak_时间戳` |
| 端口冲突（同学装了 clash/v2ray） | 体检检测 7890/1080/53 占用，冲突则提示改端口或跳过 UA3F |
| 断网时无法下载 ua3f/bitsrun | 跳过并写进报告；不阻塞主流程 |
| 单网口笔记本只能拓扑 A/C | 向导里直接过滤不可用拓扑，不给无效选项 |
| UA3F 仅 x86_64 | `uname -m` 检测，非 x86_64 跳过 |
| 密码明文 | config.env 600，srun 账号单独文件 600，报告里脱敏 |

## 7. 分阶段交付

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P1** | 抽公共层 `lib/` + 16 个脚本参数化 + `doctor.sh` | 在你 软路由主机 上 `--dry-run` 装到 `~/deploy-test/`，体检报告与实际一致，不动系统 |
| **P2** | `install.sh` / `uninstall.sh` + 拓扑 A/B/C + 认证三种 + 幂等/回滚 | 同机重复装两次不坏；卸载后 `autoconnect=yes` 复原 |
| **P3** | 打包 + 图标 + 中文文档 + 自检报告 + checksums | 单文件 zip <1MB，解压即用 |
| **P4** | Windows 端「部署」栏目（上传/执行/进度/报告） | 从 NetPanel 一键部署到 软路由主机 成功，状态页自动接管 |
| **P5** | 真机演练 + 给你"发同学"的三步说明 | 你按说明重装一遍能跑通 |

预估：P1+P2 是主体（约 2~3 小时），P3 约 30 分钟，P4 约 1 小时，P5 30 分钟。

## 8. 待你拍板的 5 件事

1. **拓扑范围**：只做 A（和你一样）？还是 A+B+C 全做？（我建议全做，B 只是多一块网卡的事）
2. **认证范围**：`none` + `srun` 够不够？要不要 PPPoE？（我建议三种都做，代码量差不了多少）
3. **ua3f/bitsrun**：改成安装时下载（我建议），还是坚持打包进 zip？
4. **Windows 端**：这一轮一起做，还是先出 Ubuntu 包、Windows 端下一轮？
5. **语言**：只中文，还是中英双语？（同学大概率中文，我建议只中文，省一半文案）

确认后我按 P1 开始动手，每完成一个阶段给你一条可验收的输出（不一次性甩一堆）。
